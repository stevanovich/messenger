# Логика скрытия уведомлений о непрочитанных сообщениях и неувиденных реакциях

## 1. Непрочитанные сообщения (прочтения)

### Backend (БД и API)

- **Кто считается непрочитанным:** сообщения в беседе, где `m.user_uuid != текущий_пользователь` и нет записи в `message_reads` для пары `(message_id, user_uuid)`.
- **Счётчик в списке чатов:** `unread_count` в `api/conversations.php` — количество таких сообщений по каждой беседе.

**Как помечаются прочитанными:**

| Действие | Когда вызывается | Что делает |
|----------|------------------|------------|
| `mark_read` | При открытии чата, если нет непрочитанных | Вставляет в `message_reads` записи для **всех** чужих сообщений в беседе. Счётчик непрочитанных становится 0. Реакции не меняются. |
| `mark_read_up_to` | При прокрутке, когда непрочитанное сообщение попадает в зону видимости | Вставляет в `message_reads` записи для всех чужих сообщений с `id <= message_id`. Возвращает новый `unread_count`. Реакции не меняются. |

### Frontend

- **Отображение:** бейдж `chat-item-unread` показывается при `unread_count > 0`. Время последнего сообщения (`chat-item-time`) скрыто, если есть непрочитанные или неувиденные реакции.
- **При открытии чата:**
  - Если есть сохранённая позиция скролла — восстанавливаем её, ставим только `setupUnreadObserver`. Ничего не помечаем прочитанным сразу.
  - Если сохранённой позиции нет:
    - Если есть непрочитанные (`hasUnread`) — скролл к первому непрочитанному, ставим `setupUnreadObserver`.
    - Если непрочитанных нет — скролл вниз и вызываем `markConversationAsRead` (действие `mark_read`), затем перезагрузка списка чатов.
- **Наблюдатель непрочитанных:** `setupUnreadObserver(container)` следит за элементами `.message[data-read-by-me="0"]`. Когда такой элемент попадает в зону видимости (threshold 0.2):
  1. Ставим `data-read-by-me="1"`.
  2. Вызываем `markReadUpTo(conversationId, messageId)`.
  3. В ответе обновляем `conv.unread_count` и перерисовываем список чатов.

Итог: непрочитанные скрываются **по мере просмотра** — при появлении сообщения в зоне видимости оно помечается прочитанным и счётчик уменьшается.

## 2. Неувиденные реакции

### Backend (БД и API)

- **Кто считается неувиденным:** реакции **других** пользователей на **мои** сообщения, для которых `mr.created_at > last_reactions_seen_at` (или `last_reactions_seen_at` пустой). Хранится одно поле на участника беседы: `conversation_participants.last_reactions_seen_at`.
- **Счётчик в списке чатов:** `unseen_reactions_count` в `api/conversations.php` — количество таких реакций по каждой беседе.

**Как помечаются увиденными:**

| Действие | Когда вызывается | Что делает |
|----------|------------------|------------|
| `mark_reactions_seen` | Сейчас почти не используется (раньше — при открытии чата) | Ставит `last_reactions_seen_at = NOW()` по беседе. Все реакции в беседе считаются увиденными. |
| `mark_reactions_seen_for_message` | При прокрутке, когда **своё** сообщение с реакциями попадает в зону видимости | Для указанного `message_id` (проверяется, что сообщение своё): берётся `MAX(mr.created_at)` по чужим реакциям на это сообщение; обновляется `last_reactions_seen_at = GREATEST(текущее, это_время)`. Возвращается новый `unseen_reactions_count`. |

### Frontend

- **Отображение:** бейдж `chat-item-unseen-reactions` (👍 N) при `unseen_reactions_count > 0`. Время скрыто при наличии непрочитанных или неувиденных реакций.
- **При открытии чата:** реакции **не** помечаются увиденными целиком (вызов `markReactionsSeen` при открытии убран).
- **Наблюдатель реакций:** после каждой загрузки сообщений вызывается `setupReactionsSeenObserver(container)`. Он находит все `.message.own`, у которых есть блок `.message-reactions`, и вешает на них `IntersectionObserver` (rootMargin 50px, threshold 0.1). Когда такое сообщение попадает в зону видимости:
  1. Один раз для этого `message_id` вызывается `markReactionsSeenForMessage(conversationId, messageId)` (дубликаты отсекаются по `Set`).
  2. В ответе обновляется `conv.unseen_reactions_count` и перерисовывается список чатов.

Итог: реакции должны скрываться **по мере просмотра** — только когда в зоне видимости оказывается **своё** сообщение с реакциями.

## 3. Обнаруженная ошибка (исправлена)

В обработчике **`mark_read_up_to`** (api/messages.php) после отметки сообщений прочитанными выполнялось:

```php
UPDATE conversation_participants SET last_reactions_seen_at = NOW()
WHERE conversation_id = ? AND user_uuid = ?
```

и в ответ всегда возвращалось `unseen_reactions_count: 0`.

**Последствие:** при каждом появлении в зоне видимости **чужого** непрочитанного сообщения (и вызове `markReadUpTo`) все реакции в беседе считались увиденными, и бейдж реакций пропадал, даже если пользователь ещё не доскроллил до своих сообщений с реакциями.

**Исправление:** из `mark_read_up_to` удалён этот `UPDATE` и из ответа убрано поле `unseen_reactions_count`. Из `mark_read` тоже удалён `UPDATE last_reactions_seen_at`. Теперь оба действия только помечают сообщения прочитанными; счётчик реакций в ответе `mark_read_up_to` не возвращается, а на фронте обновляется только если поле есть в ответе (чтобы не затирать значение нулём). Реакции помечаются увиденными **только** через `mark_reactions_seen_for_message` при просмотре своих сообщений с реакциями.

---

## 4. Краткая схема

- **Непрочитанные:** счётчик и бейдж уменьшаются при появлении в зоне видимости чужих сообщений (observer → `mark_read_up_to`) или при открытии чата без непрочитанных (`mark_read`).
- **Неувиденные реакции:** счётчик и бейдж уменьшаются только при появлении в зоне видимости **своих** сообщений с реакциями (observer → `mark_reactions_seen_for_message`). Отметка прочтения сообщений (`mark_read` / `mark_read_up_to`) больше не влияет на `last_reactions_seen_at`.
