1. Обзор

Проект поддерживает мультиалгоритмное E2EE с согласованием ключей по ECDH P-256 или ГОСТ Р 34.10-2012 (VKO) и симметричным шифрованием AES-GCM, Кузнечик-MGM или Магма-MGM. Приоритет алгоритмов задаётся только на сервере.

Типы ключей

ТипГде хранитсяНазначение
Пары ключей клиент sessionStorage, опционально localStorage (WebAuthn), сервер (публичные) Согласование общего секрета (ECDH/VKO)
Ключ беседы клиент Память (CONV_KEY_CACHE) Шифрование сообщений в личном чате
Ключ группы сервер Зашифрованные blob в conversation_member_keys Шифрование сообщений в групповом чате
Резервная копия сервер user_key_backup.key_blob Восстановление при смене устройства

2. Выработка ключей

2.1 Пары ключей пользователя

ECDH P-256 — через Web Crypto API: generateKey(ECDH, P-256), экспорт в JWK.

ГОСТ Р 34.10 (VKO) — при gost_key_agreement === 'GOST-R-34.10': приватный 64 байта, публичный вычисляется библиотекой VKO, кривая ID_GOSTR3410_2012_512_PARAM_SET_A.

2.2 Ключ беседы (личный чат)

  • ECDH: deriveBits → SHA-256 → AES-GCM ключ
  • VKO: kek_34102012256(curve, myPriv, remotePub, UKM) — UKM = SHA-256("e2ee-vko-{conversationId}")[0..8]

2.3 Ключ группы

Случайный AES-GCM 256 бит. Для каждого участника шифруется его публичным ключом и сохраняется в conversation_member_keys.

4. Использование ключей

Инициализация при загрузке

  1. GET config → algorithms, gost_key_agreement
  2. Проверка WebAuthn lock → если включена, ждём разблокировки
  3. Проверка резерва → если есть blob и нет ключей, событие e2ee-need-restore
  4. Иначе: загрузка/генерация ключей, регистрация публичных на сервере

Личный чат

  1. Получить публичные ключи собеседника
  2. Выбрать первый общий алгоритм
  3. Вывести ключ беседы, закэшировать
  4. Шифрование: ivBase64:ciphertextBase64

Групповой чат

  1. GET group_key → расшифровать своим приватным
  2. Если нет — сгенерировать, зашифровать для каждого участника, POST set_group_key
